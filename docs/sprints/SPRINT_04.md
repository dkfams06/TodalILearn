# Sprint 4 — 하이브리드 검색

상태: Complete  
시작일: 2026-07-18  
종료일: 2026-07-18

## 목표

주제·질문·성경 본문·인물·사건 입력으로 옵시디언 7개 문서와 예언의 신 5,857개 문단에서 관련 원문을 찾고, 선택 이유와 실제 원문 위치를 함께 보여준다.

## 확정 입력

```text
옵시디언 원문: 7개
옵시디언 검색 청크: 189개
예언의 신 원문·벡터: 5,857개
임베딩: Xenova/multilingual-e5-small / 384차원 / version 1
평가 세트: T1~T8
```

## 검색 원칙

- 검색 자체에는 Claude를 호출하지 않는다.
- 모든 옵시디언 문서가 동일하게 검색 가능하며 자료 등급·제외·고정 감점을 사용하지 않는다.
- 성경 참조의 정확 일치는 의미 유사도보다 우선한다.
- 한 문서의 인접 청크는 문서 결과 하나로 중복 제거하고 가장 관련성 높은 청크를 대표로 표시한다.
- 예언의 신 결과는 옵시디언 결과와 별도 목록으로 제공하며 관련성이 부족하면 수를 채우지 않는다.
- 모든 결과는 실제 레코드 ID, 원문 내용, offset 또는 책·장·청크 순번을 포함한다.

## 입력 분석 계약

결정론적 파서가 다음 값을 만든다.

```text
original_query
normalized_query
terms
phrases
bible_references
```

- 한국어 성경 이름과 일반 약칭을 표준 책 이름으로 정규화한다.
- `다니엘 7장`, `창세기 41장`, `여호수아 6:12-16` 형태를 인식한다.
- 조사·일반 질문어는 검색어에서 제외하되 원문 질의 전체는 의미 검색에 그대로 사용한다.
- AI가 성경 참조나 동의어를 새로 추론하지 않는다.

## 후보 검색 채널

### 옵시디언

1. 성경 참조 정확 일치
2. 제목·원문 텍스트 일치
3. 구조화 메타데이터 일치
4. E5 `query:` 의미 검색

구조화 메타데이터 범위:

```text
main_topic
sub_topics
main_bible_texts
supporting_bible_texts
biblical_people
biblical_events
core_message
summary
key_claims
illustrations
applications
```

### 예언의 신

1. 책·제목·본문 텍스트 일치
2. E5 `query:` 의미 검색

## 병합·랭킹 계약

각 후보에 다음 설명 가능한 신호를 기록한다.

```text
exact_reference_score
title_score
lexical_score
metadata_score
semantic_score
final_score
matched_terms
matched_references
reasons
```

성경 참조 정확 일치는 가장 큰 가중치를 갖는다. 나머지 신호는 0~1 범위로 정규화해 합산한다. 최종 점수가 같으면 정확 참조, 메타데이터, 의미 유사도, 원문 순으로 안정 정렬한다.

## API·UI 계약

```text
POST /api/search
body: { query: string }
```

응답:

```text
query analysis
옵시디언 문서 결과 최대 7개
예언의 신 결과 최대 5개
검색 시간
임베딩 모델·버전
```

화면에서는 결과별로 제목, 대표 청크, 선택 이유, 점수 신호와 원문 위치를 확인할 수 있어야 한다. 검색 오류가 동기화나 다른 설정 기능을 막아서는 안 된다.

## 평가 계약

- T1~T8을 코드에 고정하고 실행 결과를 JSON과 Markdown 요약으로 출력한다.
- T1~T6 각각 기대 문서가 상위 5개에 있어야 한다.
- T1~T6 핵심 기대 문서 중 최소 5개가 Top 3에 있어야 한다.
- 7개 모든 문서는 자기 제목 또는 대표 주제 검색에서 Top 3에 들어야 한다.
- 결과 청크의 ID·source ID·offset이 실제 DB와 일치해야 한다.
