# 품질 평가 계획

상태: Approved (2026-07-17)

## 목적

“좋아 보이는 결과”가 아니라 실제 가정예배에 사용할 수 있는 결과를 반복해서 측정한다. 자동 평가는 데이터 무결성과 검색 회귀를 담당하고, 신학·말투·사용성은 사용자가 최종 판단한다.

## 현재 평가 데이터

옵시디언 입력 폴더:

```text
C:\Users\EQR6\Documents\Obsidian Vault\05 Raw\bible
```

현재 Markdown 7개:

1. 이스라엘의 승리법칙
2. 모든 창고를 열고
3. 7월 11일 예배 설교(안)
4. 창세기 24강 — 가정과 차별금지법
5. 창세기 25강 — 공산주의와 사회 침투
6. 대한민국 운명 기독교에 답이 있다
7. 하나님이 가장 기뻐하시고 사탄이 가장 싫어하는 일

자료가 추가되면 평가 세트를 버전으로 관리한다.

## 대표 검색 테스트

### T1 — 의미 연결

입력:

```text
문제 해결보다 하나님이 함께하시는 것이 더 중요하다
```

기대:

- `이스라엘의 승리법칙`이 최상위권
- 출애굽기 33장과 여호수아 5~7장 연결
- 문제 해결과 하나님의 임재를 구분

### T2 — 관계 적용

입력:

```text
작은 일도 하나님께 묻는 관계
```

기대:

- 여리고성과 아이성 비교 청크
- 두 사람이 함께 기도하고 결정하는 적용
- 상대의 잘못을 지적하는 말투 금지

### T3 — 인물과 주제

입력:

```text
사랑은 상대를 살리는 선택이다
```

기대:

- `모든 창고를 열고` 상위권
- 요셉, 창세기 41장과 45장
- 생명을 살리는 사랑을 관계 적용으로 연결

### T4 — 가정예배 목적

입력:

```text
함께 말씀을 읽는 습관이 우리 관계를 어떻게 지켜주는가
```

기대:

- `하나님이 가장 기뻐하시고 사탄이 가장 싫어하는 일` 상위권
- 성경 읽기와 매일의 갱신
- 습관을 강요가 아니라 함께 선택하는 적용으로 표현

### T5 — 다중 문서 종합

입력:

```text
진리를 안다는 것과 진리대로 산다는 것
```

기대:

- `모든 창고를 열고`
- `하나님이 가장 기뻐하시고 사탄이 가장 싫어하는 일`
- 두 문서의 관점을 구분하면서 하나의 핵심 메시지로 종합

### T6 — 정확한 본문 연구

입력:

```text
다니엘 7장의 작은 뿔은 무엇을 의미하는가
```

기대:

- `7월 11일 예배 설교(안)` 최상위권
- 다니엘 7장 실제 본문
- 예언의 신 관련 문단이 있을 경우 정확한 출처
- 자료의 역사적 주장과 성경 본문을 구분

### T7 — 사회 주제 활용

입력:

```text
우리의 의견이 다른 사회 문제를 신앙적으로 어떻게 대화해야 할까
```

기대:

- 관련 사회 자료도 정상적으로 검색 가능
- 자료를 등급으로 제한하거나 자동 제외하지 않음
- 연인을 비난·설득하는 원고를 만들지 않음
- 자료의 주장과 AI 관계 적용을 구분

### T8 — 역사 자료 활용

입력:

```text
그리스도인은 사회를 섬기며 어떤 역할을 해야 하는가
```

기대:

- `대한민국 운명 기독교에 답이 있다`의 의료·교육·섬김 내용 검색
- 역사적 서술의 출처가 영상 대본임을 표시
- 성경적 섬김의 원리와 자료 사례를 구분

## 검색 평가 지표

- `Recall@5`: 기대 문서가 상위 5개 안에 있는가
- `MRR`: 첫 기대 결과가 얼마나 위에 있는가
- 본문 정확도: 입력한 책·장·절을 정확히 찾는가
- 출처 위치 정확도: 표시한 청크가 실제 주장을 포함하는가
- 중복률: 같은 내용이 불필요하게 반복되는가
- 무관 결과율: 선택 자료 중 설명하기 어려운 결과의 비율

초기 통과 기준:

```text
T1~T6 Recall@5 = 100%
T1~T6 기대 핵심 문서 중 5개 이상 Top 3
깨진 출처 링크 = 0
직접 인용 불일치 = 0
```

## 설교 사용자 평가표

각 항목을 1~5점으로 평가한다.

1. 성경 중심성
2. 본문 해석의 자연스러움
3. 예언의 신 활용의 적절성
4. 옵시디언 자료 활용의 관련성
5. 출처 신뢰성
6. 한 가지 핵심 메시지의 선명함
7. 연인에게 적절한 말투
8. 개인 적용과 관계 적용의 균형
9. 질문의 대화 가능성
10. 기도문의 자연스러움
11. 반복 없는 분량
12. 실제 사용 의향

전체 판정:

```text
ready: 그대로 사용 가능
minor_edit: 조금 수정하면 사용 가능
major_edit: 많이 수정해야 함
reject: 다시 작성해야 함
```

MVP 목표:

```text
첫 5편 중 4편 이상이 minor_edit 이상
출처 오류 0건
책망·설득 어조로 인한 reject 0건
```

## 수정량 측정

수정 전후 Markdown을 비교해 다음을 기록한다.

- 삭제된 문장 수
- 추가된 문장 수
- 변경된 문장 수
- 전체 문자 변화율
- 수정 사유 태그

수정 사유:

```text
theology
citation
tone
awkward_expression
repetition
relationship_application
length
question
prayer
personal_preference
```

“10% 수정”은 초기에는 엄격한 성공/실패 기준보다 추세 지표로 사용한다. 기준 설교가 5~10개 축적된 뒤 목표치를 보정한다.

## 기준 설교 축적

현재 좋은 가정예배 설교 예시는 없다. 따라서 다음 순서로 기준 데이터를 만든다.

1. 대표 주제에서 설교 생성
2. 사용자가 직접 수정
3. 수정 사유 기록
4. 최종 사용 여부 기록
5. 수정본을 기준 설교로 저장
6. 프롬프트 변경 전후를 같은 주제로 재평가

사용자 수정본을 모델 학습 데이터로 자동 전송하지 않는다. 프로젝트 내부 평가와 프롬프트 개선 자료로만 사용한다.
