# 전체 로드맵

상태: Approved (2026-07-17)

## 진행 전략

로드맵은 기능 종류별 수평 구현이 아니라, 사용 가능한 결과를 점진적으로 완성하는 수직 Slice 방식으로 진행한다.

```text
기반 확인
→ 실제 문서 동기화
→ 검색 검증
→ 연구 묶음
→ 메인 PC 실행 기반
→ 설교 생성
→ 저장·수정
→ 양방향 동기화
→ 패키징·안정화
```

## Phase 0 — 설계 확정과 기존 자산 검증

관련 Sprint: 0

목표:

- 문서 세트를 승인 상태로 전환
- 기존 Supabase 실제 스키마 확인
- 예언의 신 데이터와 기존 벡터 상태 확인
- 성경 API와 Claude Code 구독 실행 확인
- 무료 로컬 임베딩 기술 Spike

종료 조건:

- 파괴적 DB 변경 없이 구현을 시작할 수 있다.
- 임베딩 모델, 차원, runtime, 재임베딩 방법이 확정된다.
- 테스트 주제와 평가표가 승인된다.

## Phase 1 — 데이터 기반

관련 Sprint: 1~3

목표:

- 새 Next.js 프로젝트 기반 구성
- 로컬 설정과 Supabase 연결
- 만나앱 `sop_chunks`를 새 프로젝트로 검증 복사
- 옵시디언 7개 문서의 단방향 동기화
- 구조화 분석과 청크 생성
- 예언의 신과 옵시디언 청크를 같은 모델로 임베딩

종료 조건:

- 동일 파일을 재동기화해도 중복이 생기지 않는다.
- 수정된 파일만 재처리된다.
- 모든 벡터에 모델·버전이 기록된다.
- 한 문서의 실패가 전체 작업을 중단하지 않는다.

## Phase 2 — 검색과 성경연구비서

관련 Sprint: 4~5

목표:

- 정확 일치, 텍스트, 의미, 구조화 검색 통합
- 성경 API 조회와 본문 정규화
- 예언의 신 검색 통합
- 연구 묶음과 자료 선택 UI

종료 조건:

- 평가 T1~T6의 Recall@5가 100%다.
- 모든 결과가 원문 위치로 연결된다.
- 모든 옵시디언 문서가 등급 제한 없이 검색될 수 있다.

## Phase 3 — 가정예배 설교 생성

관련 Sprint: 5.5~7

목표:

- Vercel 웹과 Windows Local Companion 연결
- PC별 Obsidian 경로와 Claude 구독 실행 분리
- 연인 가정예배 고정 구조
- 출처 지도가 있는 설교 생성
- 자료 확인·변경·재생성
- 웹 편집과 Supabase 저장
- 첫 기준 설교 5편 축적

종료 조건:

- Vercel 연구 작업을 메인 PC가 자동으로 중복 없이 처리한다.
- 다른 PC에는 로컬 설치나 경로 설정이 필요 없다.
- 첫 5편 중 4편 이상이 `minor_edit` 이상이다.
- 직접 인용과 출처 오류가 없다.
- 책망·설득 어조로 인한 `reject`가 없다.

## Phase 4 — 옵시디언 완성본 연동

관련 Sprint: 8~9

목표:

- 완성 설교 Markdown 출력
- 웹 수정본 로컬 반영
- 옵시디언 수정본 서버 반영
- 버전과 충돌 처리

종료 조건:

- 메인 PC 저장본이 Obsidian 동기화를 통해 다른 PC에 반영된다.
- 충돌 시 어느 쪽도 자동 덮어쓰지 않는다.
- 모든 충돌 버전을 복구할 수 있다.

## Phase 5 — 운영 안정화

관련 Sprint: 10

목표:

- 자동 감시 선택 기능
- 재처리와 오류 복구 UI
- 백업·복원 절차
- Windows 실행 방식 정리
- 성능과 비용 관찰

종료 조건:

- 평소 사용 흐름을 문서 없이 수행할 수 있다.
- 오류 발생 후 사용자가 안전하게 재시도할 수 있다.
- 전체 회귀 테스트를 통과한다.

## 주요 의존성

```text
Sprint 0 임베딩 결정
├─ 예언의 신 재임베딩
├─ 옵시디언 문서 임베딩
└─ 검색어 임베딩

검색 품질 통과
└─ 연구 묶음 품질
   └─ 설교 생성 품질
      └─ 양방향 동기화 투자
```

## 중단 또는 재검토 조건

다음 조건이 발생하면 다음 Sprint로 넘어가지 않고 설계를 재검토한다.

- 로컬 임베딩 속도가 실제 사용에 부적합함
- 기존 예언의 신 원문에 안정적인 위치 정보가 없음
- 성경 API의 번역본 또는 사용 조건이 목적에 맞지 않음
- 대표 검색 테스트에서 기대 자료를 반복적으로 찾지 못함
- 생성 설교의 출처 오류를 자동 검증할 수 없음
- 사용자 평가에서 `major_edit`와 `reject`가 반복됨

## MVP 완료 정의

MVP 완료는 기능 목록 구현이 아니라 다음 사용자 흐름이 검증된 상태다.

```text
1. Windows에서 앱 실행
2. 옵시디언 폴더 동기화
3. 주제 또는 본문 입력
4. 성경·예언의 신·옵시디언 연구 결과 확인
5. 가정예배 설교 생성
6. 출처 확인
7. 소폭 수정
8. Supabase와 옵시디언에 저장
9. 다음 PC에서도 안전하게 동기화
```
